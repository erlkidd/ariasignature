# Changelog

Все значимые изменения в проекте фиксируются в этом файле.

Формат основан на категориях: `Added`, `Changed`, `Fixed`, `Docs`.

## [0.2.9] - 2026-05-02

### Changed
- Подсказка настроек: только про перезапуск для смены порта; расписание обновления дисков применяется сразу через перепланирование Quartz.
- UI: сообщение после сохранения настроек отражает мгновенное применение расписания дисков.

### Fixed
- Файловая архивация: сообщение «файл занят» показывается только при реальной ошибке совместного доступа (HRESULT / точная фраза), без подмены других `IOException`.

## [0.2.8] - 2026-05-02

### Changed
- Подсказка в `GET /settings` (`note`): формулировка «Расписание обновления дисков» без упоминания SMART.
- Версия продукта `0.2.8` синхронизирована в .NET, web и установщике.

### Fixed
- Файловая архивация: уникальные имена временной копии и RAR по штампу с миллисекундами — безопасные параллельные запуски нескольких задач в одну папку.

## [0.2.7] - 2026-05-02

### Changed
- В таблицах задач и журнала отображается текст пути к папке рядом с кнопкой «Открыть папку»; колонка в «Настройка задач» переименована в «Путь к базе / База данных» (для MSSQL — имя базы).
- Добавлена колонка «Последний запуск» и индикатор «Выполняется…» на время ручного запуска архивации.
- Раздел дисков: заголовок истории «История дисков»; убраны лишняя подсказка в тулбаре и блок SMART из карточки диска.
- Версия продукта `0.2.7` синхронизирована в .NET, web и установщике.

### Fixed
- Убрано двойное подчёркивание (две линии) под вкладками раздела «Архивация» при выборе «Журнал».
- MSSQL: временный `.bak` создаётся с уникальным именем (без удаления занятого файла), снижена гонка «file is being used by another process»; сообщения об ошибках ввода-вывода переводятся на русский.

## [0.2.6] - 2026-05-01

### Added
- В API добавлены операции очистки SMART-истории:
  - `DELETE /api/v1/disks/{id}/smart` — очистка по выбранному диску;
  - `DELETE /api/v1/disks/smart` — глобальная очистка истории.
- В интерфейс добавлены кнопки очистки SMART-истории с подтверждением действия.

### Changed
- Заголовок раздела деталей переименован в `Карточка диска`.
- Терминология UI унифицирована на формулировку `Диски`.
- Версия продукта синхронизирована до `0.2.6` во всех контурах: .NET, web, installer и документация.

### Fixed
- Устранен сценарий финальной ошибки инсталлятора при позднем старте службы.
- Добавлена обработка `sc create` с кодом `1078` через fallback (альтернативный `DisplayName` и запуск без `DisplayName`).
- Усилен self-heal путь регистрации службы из UI.

### Docs
- Документация приведена к единому русскоязычному техническому стилю.
- Актуализированы `API`, `USER_GUIDE`, `DEVELOPER_GUIDE`, `INSTALLER`, `RELEASE_GATE`, `INSTRUCTIONS`.
- `DEVELOPMENT_NOTES` и `CHANGELOG` синхронизированы с релизом `0.2.6`.

## [0.2.5] - 2026-05-01

### Changed
- Существенно ускорен старт службы и выход UI из экрана ожидания.
- API перенесен в раннюю фазу запуска, инициализация БД переведена в фоновый этап с таймаутом и диагностикой.

### Fixed
- Снижены риски `database is locked` за счет `WAL`, `busy_timeout`, `synchronous=NORMAL` и retry-политики.
- Стабилизирован installer: WebView2 offline runtime, корректный цикл остановки/переустановки компонентов.

### Docs
- Обновлены ключевые документы под service-first модель и релиз `0.2.5`.

## [0.2.4] - 2026-04-30

### Fixed
- Возвращен единый путь запуска через `AriaSignatureService` без локального fallback-процесса.
- Стабилизирован старт API при нестабильной инициализации SQLite.
- Усилен контур reinstall/uninstall с полной очисткой каталога установки.

## [0.2.3] - 2026-04-30

### Added
- Внедрена стратегия `smartctl-first` для телеметрии с fallback по WMI и Storage.
- В модель и API добавлены observability-поля телеметрии.

### Fixed
- Исправлены сценарии черного/белого экрана при поздней готовности API.
- Устранены ошибки миграции SQLite при обновлении.

## [0.2.2] - 2026-04-29

### Added
- Добавлен низкоуровневый канал телеметрии через `smartctl`.
- Добавлены пресеты SMART-расписания и улучшена валидация формы задач.

### Changed
- Выравнены ключевые UI-потоки и русскоязычные статусы службы.

## [0.2.1] - 2026-04-29

### Fixed
- Стабилизирован запуск API и совместимость Swagger.
- Усилен путь регистрации службы в installer.

### Docs
- Синхронизированы версии артефактов и документации.

## [0.2.0] - 2026-04-28

### Added
- Введен новый UI-слой на React SPA внутри WebView2.
- Реализованы базовые сценарии панели: диски, архивация, настройки, раздел «О программе».
- Добавлены host-интеграции UI: выбор файлов/папок, взаимодействие с сервисом, стартовые операторские сценарии.

### Changed
- Закреплена service-first модель: исполнение в службе, UI как операторская консоль.
- Обновлены контракты API под практические сценарии диагностики и архивации.

### Docs
- Базовая документация приведена к целостному русскоязычному виду.

## [0.1.x] - 2026-04 

### Added
- Сформирован архитектурный каркас проекта и разбиение на Domain / Application / Infrastructure / API / Service / UI.
- Запущен локальный API внутри Windows-службы.
- Реализован сбор телеметрии дисков и плановое обновление.
- Реализован pipeline резервного копирования и хранение данных в SQLite.
- Добавлены CRUD-операции задач, журнал выполнения, базовые тесты API.
- Добавлен installer-контур и release-gate скрипт.

### Changed
- UI-панель последовательно эволюционировала от базовой MVVM-оболочки к интерактивному SPA-опыту.
- Локализация продукта приведена к русскому языку для UI и installer-сценариев.

### Fixed
- Поэтапно устранены критические сбои старта UI/службы, проблемы tray-потока и нестабильности service lifecycle.
- Улучшена идемпотентность installer-операций stop/delete/create службы.

### Docs
- Сформирован полный комплект эксплуатационной и технической документации.

### Added
- Инициализирован репозиторий и базовая структура решения.
