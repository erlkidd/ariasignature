# Руководство пользователя AriaSignature

## Назначение

AriaSignature — локальная служба Windows и настольное приложение для:

- мониторинга состояния HDD/SSD;
- создания и выполнения задач архивации 1С;
- публикации данных наружу через локальный API для интеграции с внешними системами (например, расширением в 1С).

## Как работает система

- **Служба Windows** `AriaSignatureService` выполняет сбор телеметрии дисков, расписание архивации и поднимает **локальный HTTP API** (`AriaSignature.Service`).
- **Настольное приложение** `AriaSignature.UI` — оболочка с **WebView2**: открывает веб-панель, которую отдаёт сама служба из папки `wwwroot` (технически это те же экраны, что доступны по браузеру на `http://127.0.0.1:5160/`).
- При старте панель **пытается запустить** службу `AriaSignatureService`, если она остановлена (нужны права на запуск службы).
- API на `localhost` используется и панелью, и **внешними системами** (например 1С) для чтения уже собранных данных.

### Требование: WebView2

- Для окна панели нужен **Microsoft Edge WebView2 Runtime** (Evergreen). Если компонент не установлен, Windows покажет сообщение с подсказкой.

## Что доступно в интерфейсе (веб-панель)

- Вкладка **Накопители**:
  - список дисков и индикатор состояния (`OK` / `Warning` / `Critical`);
  - карточка: объёмы (всего / свободно / занято), температура, ресурс SSD (если доступен), часы работы, циклы включения, SMART;
  - история SMART по выбранному диску;
  - кнопка обновления (данные приходят из службы).
- Вкладка **Архивация**:
  - создание задач файловой базы (`.1CD`) и **MSSQL** с полями сервер / база / режим входа (SQL или Windows) и кнопкой **«Проверить подключение»**;
  - конструктор расписания (ежедневно / еженедельно / ежемесячно) с понятным текстом и отображением cron Quartz; опционально — ввод cron вручную;
  - папка для архивов (явно подписана как путь);
  - список задач, редактирование, запуск, удаление;
  - журнал с фильтром по статусу.
- Вкладка **Настройки**:
  - порт API и cron опроса SMART (сохраняются в SQLite; смена порта требует перезапуска службы);
  - тема оформления (светлая/тёмная);
  - автозапуск панели при входе в Windows.

## Логика архивации

- Для `File`:
  - задается путь к файлу базы (обычно `.1CD`);
  - задается папка назначения;
  - результат упаковывается в `.rar`.
- Для `MsSql`:
  - в форме задаются сервер, база и способ входа (SQL или от имени **учётной записи службы** Windows при Integrated Security);
  - перед сохранением задачи проверяется доступность подключения и базы;
  - создается backup, затем результат упаковывается в `.rar`.
- Для обеих схем:
  - работает политика хранения копий (Retention);
  - ошибки отображаются в UI и логируются.

## API для внешней интеграции

- Базовый путь API: `/api/v1`.
- Основные разделы:
  - состояние сервиса (`/status`);
  - диски и SMART (`/disks`, `/disks/{id}`, `/disks/{id}/smart`);
  - задачи архивации (`/backups`);
  - логи архивации (`/backups/logs`).

## Поведение при ошибках

- Ошибки валидации и выполнения показываются пользователю в интерфейсе.
- API возвращает структурированные ошибки в формате `application/problem+json`.
