# AriaSignature — руководство пользователя

Версия документа: 1.1.1

## 1. Назначение

AriaSignature — desktop-система для Windows для:
- диагностики дисков и хранения телеметрии;
- выполнения резервного копирования баз 1С по расписанию;
- публикации данных через **HTTP API**, в том числе **с других машин** по IP в VPN/LAN (централизованный мониторинг без RDP на каждый ПК).

Продукт рассчитан на установку у клиента с автономной работой после первичной настройки.

## 2. Компоненты и режим работы

- `AriaSignature.Service` — фоновый сервис Windows. Выполняет сбор телеметрии, планирование и выполнение задач архивации, публикацию API.
- `AriaSignatureMelezhService` — фоновый сервис Melezh (OpenIntegrations HTTP gateway, порт **7788**). См. `docs/MELEZH.md`.
- `AriaSignature.UI` — desktop-панель управления (WPF + WebView2) для администрирования.
- Локальная БД SQLite — хранение настроек, задач, журналов и срезов диагностики.

Ключевой принцип: источником телеметрии, backup-исполнения и журнала является сервис.
UI не выполняет эти процессы самостоятельно.

**Трей и автозапуск Windows**

- Иконка в **области уведомлений** (системный трей) появляется только когда запущен **`AriaSignature.UI`**. Служба Windows **не** показывает значок в трее — при работе только сервиса это ожидаемое поведение.
- Контекстное меню иконки в трее включает действия: `Открыть`, `Перезапустить службу`, `Остановить службу`, `Выход`. Для операций со службой приложение автоматически запрашивает UAC при необходимости.
- **Автозапуск панели в трее** при установке включается автоматически: ярлык в **Startup** текущего пользователя (`--tray`), запись **HKCU Run** и задача планировщика **`AriaSignatureTrayLogon`** (вход в систему, задержка 45 с). Флажок в **настройках** по-прежнему позволяет отключить автозапуск UI. Фоновая **служба** Windows ставится с типом **«Автоматически»** отдельно от окна панели.
- На **Windows 10/11** значок может оказаться в **скрытых значках** (стрелка «^» у часов) — перетащите AriaSignature на панель, если нужно видеть его всегда. Убедитесь, что в **Параметры → Приложения → Автозагрузка** для AriaSignature не выключен запуск (если запись есть).
- Диагностика: при каждом старте с `--tray` в `%LocalAppData%\AriaSignature\logs\ui-boot.log` добавляется строка (время и аргументы). Если в трее пусто, но строка есть — процесс запускался; проверьте скрытые значки.
- Повторный запуск `AriaSignature` по ярлыку не создаёт второй экземпляр и не показывает всплывающие окна: активируется уже работающее окно приложения.

## 3. Что делает сервис после установки

- запускается автоматически вместе с ОС;
- продолжает выполнять расписание архивирования без открытия UI;
- продолжает формировать диагностические данные;
- предоставляет данные через `/api/v1` для внешнего потребителя.

Журнал службы (диагностика старта и ошибок) пишется в каталог **`%ProgramData%\AriaSignature\logs\`** (файлы `service-*.log`, суточная ротация).

## 4. Требования к рабочей станции

- Windows 10/11 x64;
- Microsoft Edge WebView2 Runtime;
- права администратора для установки/обновления;
- сетевой доступ к ресурсам, куда пишутся архивы;
- для MSSQL-задач: доступ учетной записи сервиса к SQL Server и целевой БД.

## 5. Интерфейс панели

### 5.1 О системе

- сведения об узле в компактных таблицах: имя компьютера, DNS, IP-адреса активных интерфейсов, ОС, процессор, объём и доступная память, видеокарты;
- те же данные доступны через `GET /api/v1/system`.

### 5.2 Диски

- список физических дисков с текущим статусом;
- карточка выбранного диска (емкость, температура, SMART/ресурс, счетчики);
- история SMART;
- очистка истории SMART для выбранного диска;
- глобальная очистка истории SMART по всем дискам (с подтверждением);
- ручное обновление среза.

Источники телеметрии:
- primary: low-level SMART/NVMe через `smartctl`;
- fallback: WMI (`MSStorageDriver_*`, `Win32_DiskDrive`);
- fallback: Storage Reliability (`MSFT_StorageReliabilityCounter`).

В карточке диска выводятся:
- фактически использованный источник (`smartctl`, `WMI`, `StorageReliability`);
- причина деградации при частичной телеметрии (`telemetryDegradationReason`).

### 5.2 Архивация

- создание задач типов `file` (`.1CD`) и `msSql`;
- визуальная настройка расписания и расширенный Quartz-режим;
- проверка MSSQL-подключения перед сохранением;
- ручной запуск задач;
- журнал выполнения и фильтрация.

### 5.4 Настройки

- параметры API: **порт**, **привязка сокета** (все интерфейсы для доступа по IP/VPN или только localhost), опциональный **токен** для запросов не с этой машины (`Authorization: Bearer` / `X-Aria-Api-Key`);
- параметры диагностического расписания;
- **исходящая синхронизация**: URL коллектора, расписание (пресеты или расширенный Quartz, как у опроса дисков), включение; запросы на коллектор идут без заголовка `Authorization` — локальный API от этого не зависит;
- тема интерфейса;
- автозапуск UI в трей.

## 6. Модель эксплуатации

1. Установить продукт.
2. Проверить статус сервиса и доступность API.
3. Настроить задачи архивирования через UI.
4. Проверить тестовый запуск задачи и появление записей в журнале.
5. Подключить внешний контур к API службы: с вашей станции или скрипта опрашивать `http://<IP_клиента_в_VPN>:<порт>/api/v1/...` (см. [`API.md`](API.md)).

Дальнейшая работа выполняется сервисом автоматически; UI используется для изменений и контроля.

## 7. Отдача данных во внешний контур

- Базовый путь API: `/api/v1` на порту службы (по умолчанию **5160**).
- С **этого же ПК** панель использует `http://127.0.0.1:<порт>/api/v1`.
- **С другой машины** в той же VPN/LAN: `http://<IP_или_DNS_агента>:<порт>/api/v1` — при необходимости с заголовком авторизации, если в настройках задан токен.
- Основные разделы:
  - `/status`;
  - `/system` (те же данные, что вкладка «О системе»);
  - `/disks`, `/disks/{id}`, `/disks/{id}/smart`;
  - `/backups`, `/backups/logs`.
- Дополнительно агент может **сам отправлять** JSON на ваш HTTPS/HTTP endpoint по расписанию (настройки в разделе «Исходящая синхронизация»). Это не отменяет опрос API по `GET`.

Формат ошибок API: `application/problem+json`.

## 8. Ограничения и примечания

- Точность SMART зависит от поддержки диска/контроллера/драйвера и уровня доступа.
- Отсутствие отдельных полей телеметрии допустимо для части оборудования.
- Смена **порта** или **режима привязки** (localhost / все интерфейсы) требует перезапуска службы.
- Установщик создаёт правило брандмауэра для **TCP 5160**; если порт изменили — обновите правило вручную.

## 9. Ошибка 1053 при запуске службы

Код **1053** в сообщении диспетчера служб (или после `sc start`) означает: Windows **не дождалась** сигнала «служба запущена» за отведённое время SCM. На медленном диске или при активном антивирусе первый холодный старт процесса службы может занять дольше лимита, хотя служба затем всё же переходит в состояние «Работает».

Что делать:

1. Откройте **`services.msc`**, найдите **AriaSignatureService**, проверьте состояние через **10–60 секунд** после ошибки.
2. Посмотрите журнал **`%ProgramData%\AriaSignature\logs\service-*.log`** — есть ли ошибка bind порта, падение до поднятия API и т.п.
3. Убедитесь, что порт по умолчанию (**5160**) не занят другим приложением и что политики безопасности не блокируют локальный HTTP на loopback.

Панель при этом может дополнительно ждать переход службы в **Running**, если SCM уже вернул 1053, но процесс службы продолжил запуск.
